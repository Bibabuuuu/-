## RB-Y1 必须处理的缺口

1. **同名版本的参数并不完全一致。** 17 个关节的位置范围在 URDF 与 MJCF 间不同。30 个同名刚体的质量比较中，4 个左臂刚体的差异超过 0.0001 kg；例如 `link_left_arm_1` 为 URDF 2.27287031 kg、MJCF 1.88139 kg。不能用 URDF 建 MATLAB 控制模型、再用这份 MJCF 仿真而声称两边参数一致。本轮没有据此判断哪一份是真机正确值，也未完成全部坐标变换和惯量张量的一致性核验。
2. **默认电机限值不能用于能力论证。** MJCF motor 输入范围统一为 ±3,000,000，gear=1；这不是可信的物理力矩上限。URDF 提供了腰臂 effort 和速度字段，但车轮没有 effort 字段，头部和手指的 1000 值也不能直接当作经过核实的能力。速度、加速度字段的存在不代表 MuJoCo 自动硬限制这些量。
3. **通用动力学默认值需要重新审查。** 编译后所有 34 个广义速度方向均继承 armature=10、damping=50，包含浮动基和手指。armature 是附加到广义惯量对角的量，各类自由度单位不同；统一值会明显改变制动、关节响应和计算出的能力边界。不能无依据地全改成零，也不能当成厂家标定数据。
4. **机器人自碰撞默认关闭。** 610 个碰撞几何体采用 contype=1、conaffinity=0，机器人自身这些几何体之间不生成碰撞；与地面的碰撞仍存在。零自碰撞报告不能证明两臂和躯干没有几何穿插。后续须配置接触掩码和相邻连杆排除表，并检查工作姿态。
5. **夹爪目前只有关节和几何，没有驱动。** 四个手指关节没有执行器，本轮没有验证抓持。后续必须定义夹爪驱动/耦合、夹持力限制、指面摩擦和载荷接触。焊接载荷只可用于明确标注的刚性连接诊断，不可用于证明不滑落。
6. **底盘支撑不能直接照搬。** 模型只有左右驱动轮运动关节，其他底部结构随 base 刚性运动；初始 base 与地面也有接触，最大穿透约 2.63 mm。需要核对支撑轮/脚轮的滚动机制、轮胎接触和制动力矩。本轮受限驱动几乎不移动，可能与这些支撑接触、通用阻尼和诊断力矩上限共同有关，尚未独立定位每个因素的作用。

[厂商机械文档](https://rainbowrobotics.github.io/rby1-dev/hardware/mechanical_part.html)区分连续、重复峰值和瞬时峰值力矩，也说明物理范围与控制范围可能不同。因此，URDF effort、文档连续力矩和 MJCF 不能任选最大值拼成“机器人能力”。建议后续建立每关节参数来源表：先采用有依据的保守工作包络；峰值持续时间未知时，不把峰值当作持续能力。

## TIAGo 必须处理的缺口

1. **原始场景初始化悬空。** floor 在 z=-0.99 m，而 base 默认 z=0。零输入推进 0.25 s 后下降 0.3090 m，符合自由落体，尚未落地。诊断时仅在初始化把 base 放到 z=-0.989 m，并设升降关节 0.1 m；没有修改原始场景文件。
2. **全向轮接触被简化。** 四轮实际碰撞体为普通圆柱，未包含独立滚子机构。本次只测试直行，不能据此声称横移、侧向摩擦和全向紧急制动真实。
3. **默认轮速伺服对数值配置敏感。** kv=2000、步长 2 ms 的场景在本轮速度命令下产生明显异常；减小步长或降低增益显著改变结果。尚不能直接拿默认值研究停车距离。
4. **力矩上限需分层读取。** 轮子 ±400、升降 ±500、机械臂例如 ±43/±26/±3/±6.6，位于 joint 的 actuatorfrcrange；不能仅因 actuator 自身没写 forcerange 就判断无上限。它们仍是源模型数值，未取得真机对应版本的逐项标定证明。
5. **说明文档和实际模型有漂移。** README 中写添加的 base 质量为 28.26649 kg，当前 MJCF base 实际为 59.53854 kg；本报告采用编译值，没有用 README 旧数值计算惯性。

## 实际完成的最小诊断

环境和配置：MuJoCo 3.17.0；原始场景步长 0.002 s。RB 原始积分器 Euler，TIAGo implicitfast。四个场景均编译成功；检查姿态下质量矩阵最小特征值分别为 RB 10.00062、TIAGo 0.00020210，均为正；有质量刚体的主惯量未发现非正值。这只证明该姿态下的数学可计算性，不能证明质量、惯量和接触具有实物精度。

诊断控制器仅用于检查模型是否能经控制输入运动：motor 使用 PD＋偏置力补偿，其他保留原位置/速度伺服；没有实现 NMPC 或 WBC。RB 腰臂控制输出按对应 URDF effort 裁剪，头部额外诊断上限 2 Nm、轮子 20 Nm；轮子上限是保守试验设置，不是已经核实的真机能力。TIAGo 使用源模型关节级力矩限制。

初始化之后只写 ctrl 并调用 mj_step；不回写 qpos/qvel，不添加外部虚拟推力，不连接硬件。测试起始姿态为原始零关节位姿，TIAGo 仅另外设置升降 0.1 m；尚不是共同搬运姿态。

| 检查 | RB-Y1 | TIAGo |
|---|---|---|
| 未改场景零输入 0.25 s | 状态有限；初始地面穿透存在 | 状态有限；自由下落 0.3090 m |
| 调整初始化后空载保持 3 s | 最大底盘倾角 0.214°；无引擎警告 | 最大底盘倾角 0.0061°；无引擎警告 |
| 左肘小幅目标变化，3 s 总时长 | 目标 -0.03 rad，最终变化 -0.030015 rad | 目标 +0.03 rad，最终变化 +0.026916 rad |
| 底盘短距离命令，3 s 总时长 | 前进约 1.30 mm，未达到可用的行驶响应 | 原始配置前进约 1.445 m、最大倾角 28.19°，不能接受为该小幅命令下的正常结果 |

底盘命令均为：0～0.5 s 静置，0.5～1.0 s 将各轮目标角速度幅值升至 1.5 rad/s，保持至 1.5 s，1.5～1.8 s 降为零，至 3 s 观察停止。两种机器人的轮径和驱动实现不同，此测试不是两平台停车性能排名。

## 研究问题的接口边界

厂商文档明确 RB-Y1 的实体按钮和遥控 E-stop 会切断动力。[来源：E-Stop Basics](https://rainbowrobotics.github.io/rby1-dev/getting-started/estop-basics.html)。因此本课题应定义为：**底盘遇险后快速受控制动，腰部与双臂驱动在制动期间仍可用**。不能表述成按下该平台断电按钮后，手臂仍主动执行补偿；也未验证真机支持所需的分区制动时序。

实时接口公开了 target、feedback_gain、feedforward_torque，以及位置、速度、电流、力矩反馈。[来源：ControlInput & ControlState](https://rainbowrobotics.github.io/rby1-dev/sdk/cpp/client/control-loop-types.html)。这支持进一步研究控制接口适配，但不能据此保证任意固件都开放无约束直接力矩控制，或把计划中的控制频率当作实测频率。

## 下一阶段建议和完成条件

下一阶段 **待开始**：以 RB-Y1 为优先对象形成“参数自洽、底盘可真实滚动、执行器有界”的最小研究模型。当前先不展开完整 NMPC、VLA 或大规模载荷扫描。

1. **统一参数来源。** 制作每关节/刚体参数映射，明确哪些采用 URDF，哪些采用 MJCF，哪些只是仿真假设。解决质量和范围冲突，复核惯量坐标和单位。MATLAB 与 MuJoCo 共用这套参数；至少比较若干姿态下的末端位置、重力项和质量矩阵，不能直接假定两个文件等价。
2. **使底盘具有可解释的驱动和制动。** 处理支撑轮与轮地接触，选定保守有界驱动；低速空载直行、减速、停车保持先通过，并检查步长和增益敏感性。来源不足的轮胎摩擦、驱动/制动参数标为区间假设，先做边界分析，不编造“官方制动距离”。
3. **补齐有效的夹持接触。** 配置夹爪驱动和摩擦约束，先双臂静态持一个刚体，检验载荷重力由接触与关节驱动承担。载荷不固定在世界或手上；记录夹持力、相对滑移和姿态。载荷质量从已核实能力允许的范围起步。
4. **形成首个可检验问题。** 在同一底盘制动曲线下，比较“保持原关节姿态”和“简单制动加速度前馈补偿”，看末端/载荷冲击、姿态、滑移及力矩饱和。只有基线暴露了有意义的能力冲突，才继续完整优化控制器。

本阶段已交付的是候选审查和可复现实验入口，不含载荷、双臂闭链、真实夹持、制动补偿效果、控制实时性或创新性验证。若 RB-Y1 支撑和接触修整代价过高，可以回退 TIAGo 的直行版本，但需承认研究构型变为升降柱而非六关节腰部。
